x402 in 30 seconds

HTTP has had a status code for "you haven't paid" since 1997 — 402 Payment Required. x402 turns that unused code into a machine-readable payment handshake. The server does not just say "pay"; it says exactly what to pay, in which token, on which network, to which address, for which exact resource.

1

Request

You POST to a resource like a normal API call.

2

402 + challenge

Server replies 402 with a JSON challenge describing the price.

3

Pay & sign

You build a signed payment payload and send it in a header.

4

Retry → 200

Same request again. Server settles on-chain and returns the data.

The whole protocol is one screen.

No OAuth. No dashboard. No API key to leak. The challenge is self-describing JSON, the payment is a signature, and the receipt is on-chain. An agent can discover a paid endpoint, pay it, and read the answer — with no human in the loop.

# 1. You ask for something
POST /v1/verify/claims
{"claims":["The contractor must deliver by 2026-03-01."],"sources":[{"url":"https://example.com/c.txt"}]}

# 2. Server says: 402 — and hands you the exact invoice
HTTP/1.1 402 Payment Required
{"x402Version":1,"error":"payment_required",
 "accepts":[{"scheme":"exact","network":"base","maxAmountRequired":"50000",
             "asset":"0x833589fC…","payTo":"0xe23d9C54…","resource":"https://…/v1/verify/claims"}]}

# 3. You sign a payment for that nonce, put it in a header
PAYMENT-SIGNATURE: base64url(x402-v1-payment-payload)

# 4. Same request again → 200 with the data

Why you may be seeing a snapshot.

    
The endpoint above does not send Access-Control-Allow-Origin, so a browser on a different origin cannot read the 402 body — the request goes out, but the browser hides the response. This is a normal server-side posture, not a broken service: curl, Python, Node, and any agent runtime read it directly.

    
If CORS is enabled later, this page automatically shows the live challenge instead. The snapshot is the real response, captured from the live endpoint.

  


  
Copy-paste integration

  
Both snippets use only the standard library — no SDK, no dependencies. The 402 body is the challenge: parse it, sign a payment, retry.


  

    
    
    
  


  

    

      

# stdlib only. Python 3.9+
import json, urllib.request, urllib.error

SERVICE = "https://documents-planned-sent-ought.trycloudflare.com"
URL = SERVICE + "/v1/verify/claims"

body = {
    "claims": ["The contractor must deliver the API by 2026-03-01."],
    "sources": [{"url": "https://example.com/contract.txt"}],
    "minimum_sources": 1,
}

req = urllib.request.Request(
    URL,
    data=json.dumps(body).encode(),
    headers={"Content-Type": "application/json"},
    method="POST",
)

try:
    with urllib.request.urlopen(req) as r:
        print(r.status, r.read().decode())          # 200 + data
except urllib.error.HTTPError as e:
    challenge = json.loads(e.read())               # 402 body IS the challenge
    accept = challenge["accepts"][0]
    print("402 — pay", accept["maxAmountRequired"], accept["extra"]["name"])
    print("to", accept["payTo"], "on", accept["network"])

    # Build + sign the x402 v1 PaymentPayload for this nonce, then retry:
    #   headers={"PAYMENT-SIGNATURE": base64url(payload)}

    

  


  

    

      

// No dependencies. Node 18+ / any modern browser.
const SERVICE = "https://documents-planned-sent-ought.trycloudflare.com";
const URL = SERVICE + "/v1/verify/claims";

const body = {
  claims: ["The contractor must deliver the API by 2026-03-01."],
  sources: [{ url: "https://example.com/contract.txt" }],
  minimum_sources: 1,
};

const res = await fetch(URL, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(body),
});

if (res.status === 402) {
  const challenge = await res.json();            // the 402 body IS the challenge
  const accept = challenge.accepts[0];
  console.log(`402 — pay ${accept.maxAmountRequired} ${accept.extra.name}`);
  console.log(`to ${accept.payTo} on ${accept.network}`);

  // Build + sign the x402 v1 PaymentPayload for this nonce, then retry:
  //   headers: { "PAYMENT-SIGNATURE": base64url(payload) }
} else {
  console.log(res.status, await res.json());     // 200 + data
}

What you are paying for

  

    
$0.05 per call
50000 atomic USDC on Base. Fixed price, no tier, no minimum.

    
Claim verification
Verify a claim against sources. Returns a verdict plus a verbatim evidence receipt: source URL, exact quote, confidence.

    
Content extraction
/v1/extract — one URL per call returns clean markdown, title, byline, excerpt.

    
No account
No signup, no API key, no dashboard. A wallet and a signature are the only credentials.

  


  
Details developers ask for

  
    
    
  • Scheme is exact. The price is fixed, not negotiated. maxAmountRequired is the maximum you will ever be charged.
    • 
    
  • maxAmountRequired is atomic. 50000 = 50000 / 10⁶ USDC = $0.05. USDC has 6 decimals.
    • 
    
  • resource is the paid URL. The nonce is bound to it — a signature for one resource will not work on another.
    • 
    
  • maxTimeoutSeconds bounds the nonce. 300s here. Pay inside the window or fetch a fresh challenge.
    • 
    
  • outputSchema describes the response. It lets agents validate answers before they pay — and lets indexes like Bazaar v1 ingest the endpoint.
    • 
    
  • The payment-required response header carries the same challenge as a base64url blob, for clients that read headers instead of bodies.
    •
